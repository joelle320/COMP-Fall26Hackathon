# Five-minute enterprise demonstration script

Start the local server with the included built dashboard. Open `http://127.0.0.1:8000` and connect the administrator credential. Use synthetic data only; keep credentials out of the presentation capture. Open the actual generated evaluation report before quoting measurements.

**0:00 — Product and boundary.** “SENTINEL asks what AI agents are doing and whether identity activity deserves investigation. AgentGuard independently enforces supported tool policy. AccountWatch supplies explainable identity context. This is an original local prototype with proposed Cisco ecosystem mappings, not an official Cisco integration.” Point to the persistent synthetic/mock labels and the preserved AgentGuard navigation.

**0:35 — Normal operations.** Load the synthetic enterprise data. Show employee/service identities, personal baseline ranges and role context. Run the normal phase: familiar, authorized identity activity and a permitted agent read. “Baselines come from a separate normal-history split; replayed attacks do not train the detector.”

**1:15 — Detection and association.** Run the threat phase. Select the identity to show repeated failures, unfamiliar-device authentication and unusually sensitive resource access. Show reason codes, the observed-versus-normal range and the priority explanation. “An unusual event is not proof of malicious intent. This score is investigation priority, not attack probability.”

**2:00 — Independent AgentGuard enforcement.** Show the linked agent's synthetic credential-transfer attempt being blocked before the mock outbound sink receives it. Open the unified investigation and trace identity → authentication session → agent/delegate → tool → resource → event → decision. “These edges are explicit persisted bindings. We are showing a supported association, not inferring causation from timing.”

**2:45 — Investigation and proportional response.** Record an analyst note, request verification or propose containment for the named synthetic authentication session. Show that applying a scoped response needs administrator approval. Show original/proposed agent repair scope, authorize the repair, apply and inspect validation, then explicitly review restoration. No production policy changes, credential rotation or account-wide disabling occur.

**3:40 — The fifth feature: detector misses, authorization still holds.** Run the resource-authorization demonstration. The Acme agent can read its normal ticket; the other ticket is blocked both with the flagged instruction and the predefined simulated miss. “The detector signals here are simulated for comparison. The actual account policy is checked independently on every tool call.” Show the safe authorized reply and absence of the other account's private ticket body.

**4:15 — Benign exceptions and review.** Show approved travel or verified after-hours work without unnecessary enforcement. Mark a suitable unusual event expected, inspect the review history, and explain close/reopen. “Review can correct an inference; it cannot approve away a mandatory data, destination, capability or account restriction.”

**4:40 — Evidence and limits.** Show current test/evaluation evidence and the denominator of each quoted result. Note synthetic fixtures, local mock connectors, gateway-only IDE protection, local audit assumptions and any unavailable browser verification. “The value is accountable human supervision across observed identity activity and independently enforced agent actions.”

For a terminal-only fallback, run `python -m sentinel enterprise-demo --phase all --approve-sandbox-recovery`. This explicitly simulates the local administrator role; it is not autonomous approval.
